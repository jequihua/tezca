# Qualification and limits of this source checkout

This is the unreleased `0.1.0.dev0` source projection for local engineering use.
Follow the [quickstart](guides/quickstart.md) and [API cheat sheet](../08_pkg/docs/api_cheatsheet.md).
The earlier wheel-only candidate, native receipts/reviews, governance, scientific
tests and private evidence are unavailable here. Their recorded observations
below are historical evidence, not commands to rerun an absent framework.
Sharing, publication and redistribution remain unauthorized; no license is chosen.

## Engineering evidence and exact environments

Accepted S03 r2 engineering verification recorded stable exit 0 with **149 core
tests**, all **127 required IDs**, plus YAML **3**, EcoFill **4** and models **6**.
The preceding S01 r37 recorded 143 core/all 121 required IDs plus the same optional
counts. The final holistic review accepted the restricted engineering candidate;
it disclosed earlier implementation of S01 corrections by that reviewer. Separate

python-dateutil 2.9.0.post0, pytz 2026.5, tzdata 2026.5 and six 1.17.0, with setuptools

YAML used PyYAML 6.0.3; EcoFill used the admitted 0.0.1 snapshot on CPython 3.12.10
with the same numeric pins; models used scikit-learn 1.8.0, joblib 1.5.3 and
threadpoolctl 3.6.0 on CPython 3.11.9. No other platform/version combination is
qualified merely by the package's declared ranges. No optional integration is
newly qualified by this source projection.

The local projection gate builds from the actual front checkout offline, compares
package bytes with accepted source, installs into fresh core scratch, checks
optional absence, executes observed/supplied delivery and fresh validated reload,
checks all 18 export families and runs the stdlib reader and API inventory. Its
operator report is retained in development only. It supplements these receipts;
it does not rerun the scientific suite. A rebuilt wheel may have different archive
bytes from the earlier candidate; no byte-identical claim is made.

## Source identity and retained limitations

`.front_repo_sync.json` at checkout root binds source commit, truthful dirty flag,
projection manifest SHA-256 and every managed file's raw SHA-256. The included
`pyproject.toml` and `08_pkg/src` retain the working build layout; no dependency
store, retained binary candidate, raw measurement or legacy snapshot is included.
Keep built-wheel hashes and expected analysis identities independently. Integrity
checks do not authenticate an author, settle rights or prove scientific validity.

- Reload cannot recover omitted raw cells, summary PSD or eligibility of omitted
  non-contributing candidates. Coherent replacement needs a separately trusted
  expected identity. No executable model is deserialized. Window/timeline boundary
  rows retain their earlier checks outside the final r37 clock-phase binding.
- Fixed-width Unicode arrays with excessive padding or uneven lengths can exceed
  the export allocation bound; use the documented object-string representation.
  See [migration and limitations](guides/migration_and_limits.md).
- Prior Windows symlink-refusal execution was unavailable. An earlier unexplained
  example bundle-identity difference remains recorded; later deterministic tests
  do not erase it.
- Q004 development-tooling qualification relied on self-contained recovery tests.
  Four template-era framework modules retain pre-existing project-fixture failures;
  the native product gate does not execute that recovery suite. Authority checks
  bind identity without interpreting meaning; symlink recovery was unavailable.
  These tools and private records are excluded and are not requalified here.
- **R35-F3 remains carried development-tooling work:** with no execution deadline,
  an escaped descendant holding an output pipe can leave verification waiting
  indefinitely. It cannot create a false passing receipt. The architect owns
  follow-up; the front smoke is not a repair or qualification of that verifier.
- There is no automatic completion, plotting API, rendering dependency or notebook
  implementation. Downstream work can follow the [visualization guidance](../docs/visualization_guidelines.md).

Q001 parity, Q002 domain/real-data evidence and Q003 rights remain open. Their
named maintainers, data stewards, owner and rights holders must supply evidence
and authority to the architect before the corresponding claims/actions.
